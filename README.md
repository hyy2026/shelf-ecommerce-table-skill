# shelf-ecommerce-table-skill

一个纯 Markdown 的货架电商报表分析 skill：先读懂原表，再用一轮选择题确定问题、指标、维度与口径，最后生成可核验的新表和三句话总结。

**不做 HTML 网页，不提供前端演示器，不需要安装依赖。** 它的交付物是给 AI 阅读和执行的流程，不是自动接入业务数据的程序。

## 适合解决什么问题

- **涨跌诊断**：GMV 为什么变了，先区分访客、转化、客单、退款等方向。
- **结构对比**：在数据支持的前提下，按品类、SKU、会员 / 非会员或价格带比较。
- **渠道对比**：在相同时间与统计口径下，定位值得进一步核验的渠道差异。

不猜未知口径、不改原数字、不编缺失数据。解释方向不等于结论，指标变化不等于因果证明。

## 怎么用

1. 将 `SKILL.md` 的全文交给支持文件或文本上下文的 AI；若工具支持技能加载，可按该工具的约定加载此文件，不依赖某一种客户端。
2. 提供脱敏后的 Markdown 表或表格文本，附已知时间范围、金额单位、字段定义与合计。不要只说“帮我分析”。
3. 要求 AI 按五步执行：**读表 → 提问 → 给思路 → 做新表 → 收尾**。
4. AI 在第 2 步一次性给出最多 5 道选择题后应暂停；你一次答复，可同时附上已有的补充数据。AI 不替你选择，也不进行第二轮追问。
5. 若缺数据，AI 应先写“缺 XX 数据”，再给空表头；未知口径保留“待确认”。后续可由你主动补数后更新，不能让 AI 编数补齐。

**私下使用时请先把公司名和真实商品名脱敏再喂给 skill。** 同时注意订单、用户标识等敏感信息，不要提交不必要的明细。

可直接使用这段指令：

```text
请阅读并遵循随附的 SKILL.md。
我将提供脱敏后的报表和已知口径，请按五步顺序执行。
第 2 步只问一轮、最多 5 道选择题，问完先等我答复。
未知口径写“待确认”；缺数据写清字段，再给空表头，不要编数。
```

## 一个完整示例

> **模拟数据，非真实公司数据。** 以下与 `examples/` 为同一个案例，仅使用虚构的渠道甲、渠道乙，不含真实公司名、真实 SKU 名或真实报表截图。

### 用户首次输入

“GMV 跌了，请帮我看一下。”金额为人民币元，GMV 是支付订单金额，含运费、退款前，不含未支付和已取消订单。两周均为已结束的周一至周日。

| 渠道 | 上周 GMV（2025-06-02 至 2025-06-08） | 本周 GMV（2025-06-09 至 2025-06-15） |
| --- | ---: | ---: |
| 渠道甲 | 70,000 | 38,000 |
| 渠道乙 | 30,000 | 30,000 |
| 合计 | 100,000 | 68,000 |

### 第 1 步：读表

- 已有指标：GMV，单位元；已有维度：渠道；时间：连续两个完整周。
- 上周 70,000 + 30,000 = 100,000，本周 38,000 + 30,000 = 68,000，与合计差额均为 0。
- 待确认：优先指标、主指标、拆分层级、比较期、转化率分子分母、客单价分母、访客去重及退款归属。只有 GMV 不能判断转化变化。

### 第 2 步：提问并暂停

1. 具体问题是什么？**涨跌诊断 / 结构对比 / 渠道对比**（单选）。
2. 先看哪几个指标？**GMV / Net（GMV - 退款）/ 访客 / 转化率 / 客单价 / 退款率 / 会员 Net 占比**（多选，指定一个主指标）。
3. 拆到哪一层？**渠道 / 品类 / SKU / 会员 / 非会员 / 价格带**（可多选，其中“会员 / 非会员”为同一拆分选项）。
4. 口径怎么定？时间窗口：**单周 / 本月 / 累计**；退款归属：**退款算在退款周 / 待确认**；转化率分母：**访客 / 待确认**；转化率分子：**支付买家数 / 支付订单数 / 待确认**（每组选择）。
5. 跟谁比？**上周 / 上月 / 去年同期**（单选）。

此时 AI 等待，不提前输出后续步骤。

**用户一次性答复并主动补数：**涨跌诊断；选 GMV、访客、转化率、客单价，主指标 GMV；按渠道；单周、退款算在退款周、转化率分子为支付买家数、分母为访客；对比上周。另确认客单价 = GMV ÷ 支付订单数。

访客、支付买家数在周内去重，且在本模拟数据中渠道间互斥、可以相加。每名支付买家每周恰好一笔支付订单。补充数据的时间与原表一致，合计为独立核对数。

| 渠道 | 上周访客 | 本周访客 | 上周支付买家数 | 本周支付买家数 | 上周支付订单数 | 本周支付订单数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 渠道甲 | 10,000 | 10,000 | 350 | 190 | 350 | 190 |
| 渠道乙 | 5,000 | 5,000 | 150 | 150 | 150 | 150 |
| 合计 | 15,000 | 15,000 | 500 | 340 | 500 | 340 |

补充核对：两周访客均为 10,000 + 5,000 = 15,000；上周支付买家数及支付订单数均为 350 + 150 = 500，本周均为 190 + 150 = 340，与独立合计差额均为 0。不新增提问。

### 第 3 步：给思路

沿用用户选择的**渠道**维度，先列三条待验证方向，不先认定原因：

1. 可能是流量规模下降，按渠道比较访客。
2. 可能是转化效率下降，按渠道比较支付买家数 ÷ 访客。
3. 可能是每笔订单金额下降，按渠道比较 GMV ÷ 支付订单数。

### 第 4 步：做新表

格内均为“上周 → 本周”，最后两列以 GMV 为主指标。

| 渠道 | GMV（元，上周 → 本周） | 访客（人，上周 → 本周） | 转化率（上周 → 本周） | 客单价（元/单，上周 → 本周） | 环比（GMV） | 绝对变化（GMV，元） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 渠道甲 | 70,000 → 38,000 | 10,000 → 10,000 | 3.50% → 1.90% | 200.00 → 200.00 | -45.71% | -32,000 |
| 渠道乙 | 30,000 → 30,000 | 5,000 → 5,000 | 3.00% → 3.00% | 200.00 → 200.00 | 0.00% | 0 |
| 合计 | 100,000 → 68,000 | 15,000 → 15,000 | 3.33% → 2.27% | 200.00 → 200.00 | -32.00% | -32,000 |

**公式、分母与口径：**

- GMV：已确认的支付订单金额求和，人民币元，含运费、退款前，不含未支付及已取消订单；无比率分母。
- 访客：每周去重访客数，人；无比率分母。本模拟数据跨渠道互斥才允许相加。
- 转化率：支付买家数 ÷ 访客，分母为对应渠道、对应周的访客；合计按 500 ÷ 15,000、340 ÷ 15,000 重算，不平均渠道比率。
- 客单价：GMV ÷ 支付订单数，单位元/单，分母为对应支付订单数；合计按总 GMV ÷ 总支付订单数计算。
- 环比：（本周 GMV - 上周 GMV）÷ 上周 GMV；绝对变化：本周 GMV - 上周 GMV，单位元。比率的绝对变化另用百分点表示。
- 时间窗口：本期 2025-06-09 至 2025-06-15；比较期 2025-06-02 至 2025-06-08，均完整 7 天。
- 退款口径：退款算在退款周；本表未计算退款相关指标。无退款金额，不能判断 Net。
- 原始精度计算；GMV 展示到元，客单价及百分比四舍五入到两位小数。缺失不当 0，分母为 0 时比率不可计算，比较期为 0 时相对变化不可计算；本例无零分母。

**核验：**渠道甲访客与客单价不变，转化率从 **3.50% 降至 1.90%**，下降 **1.60 个百分点**。由于本例支付买家数等于支付订单数，10,000 ×（1.90% - 3.50%）× 200 = -32,000 元，正好对应下降额。这定位到转化指标变化，而非访客规模下降；尚不能证明转化下降的具体业务原因。

### 第 5 步：三句话收尾

1. **总盘怎么了：**本周 GMV 从 100,000 元降至 68,000 元，减少 32,000 元，周环比下降 32.00%。
2. **哪个维度贡献最大：**渠道甲贡献全部 32,000 元净下降，访客和客单价不变、转化率从 3.50% 降至 1.90%，但具体原因仍待验证。
3. **下一步去哪里验证：**查看渠道甲访问—商品详情—下单—支付漏斗及订单明细，核验流量质量、缺货或支付异常，当前周表不能证明是哪种原因。

- **先对总数再拆维度。**
- **小样本的百分比不下结论。**

完整交互与逐项计算见 [模拟输出](examples/模拟输出.md)。
